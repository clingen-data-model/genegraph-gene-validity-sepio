* Migration Testing Plan

Interactive REPL-based test strategy for validating schema migration changes
incrementally during development and comprehensively before release. All code
is intended to live in =genegraph.user= or a new =genegraph.migration-test= namespace.

** Event Sequence Structure

The event store files (=gene_validity_complete-<date>.edn.gz=) are compacted Kafka
logs. Each file contains the full history of all curations up to its snapshot date,
with events ordered chronologically by Kafka offset. This has two important
consequences for testing:

1. *SOP version correlates with position.* Earlier events (lower offsets) are older
   curations, predominantly on SOP 4–7. Later events carry newer SOP versions (8–11).
   Old SOP curations that have been recurated appear again later in the sequence under
   newer SOP versions — so the same GDM UUID can appear multiple times with different
   SOP versions as it is recurated.

2. *Input schema has evolved.* The GCI JSON structure has changed across years. Fields
   present in newer curations (e.g., =sopVersion= declared explicitly, newer evidence
   sub-fields) may be absent in older ones, and vice versa. The GCI → RDF parsing code
   in =gci-model.clj= must handle both, and test coverage must include both early and
   late events to catch regressions in either direction.

When looking for specific SOP versions or evidence types, target specific regions of
the event sequence: =take= from the front for old SOPs, =take-last= or filter by
timestamp for newer ones. For complete coverage of a single GDM's history across
multiple SOP versions, filter by UUID across the entire sequence.

** Design Principles

- Tests run against real transformed events, not mocks
- Incremental: run a small, curated sample while making changes; switch to full
  corpus for release validation
- Results surface as concise summary maps suitable for =tap>= / Portal inspection
- Each schema cleanup fix maps to at least one specific assertion
- The same test functions work at both scales by taking a sequence of events
- Sample corpus must include both early (old SOP, old GCI schema) and late (new SOP,
  new GCI schema) events to catch regressions in both directions

** Sample Corpus

(defn load-corpus
  "Load and transform all events for UUIDs in sample-corpus from source-file.
  Scans the full event sequence so that a GDM with a long recuration history
  yields all of its versions (old SOP, new SOP, different GCI input schemas).
  Returns a map of uuid -> vec of transformed events in sequence order."
  [source-file corpus]
  (let [uuids (set (map :uuid corpus))
        uuid-pattern (re-pattern (str/join "|" uuids))]
    (event-store/with-event-reader [r source-file]
      (->> (event-store/event-seq r)
           (filter #(re-find uuid-pattern (::event/value %)))
           (map transform-curation)
           (group-by #(re-find uuid-pattern (::event/value %)))
           (into {})))))

(defn load-epoch-sample
  "Load a sample of N events from the front and N from the back of the event
  sequence to cover both old-SOP/old-schema and new-SOP/new-schema events.
  Use this to supplement the UUID-based corpus with broad coverage."
  [source-file n]
  (event-store/with-event-reader [r source-file]
    (let [all (event-store/event-seq r)
          front (take n all)
          back (take-last n all)]
      (->> (concat front back)
           (map transform-curation)
           (into [])))))
#+end_src

** Test Functions

*** Core Assertion Infrastructure

#+begin_src clojure
(defn check
  "Run a single named check fn against a model.
  check-fn takes a model and returns truthy on pass."
  [check-fn label model]
  {:label label
   :result (if (check-fn model) :pass :fail)})

(defn run-checks
  "Run all checks against a single transformed event.
  Returns a map with the event's IRI and per-check results."
  [checks transformed-event]
  (let [model (:gene-validity/model transformed-event)]
    {:iri (::event/iri transformed-event)
     :key (::event/key transformed-event)
     :results (mapv (fn [{:keys [label check-fn]}]
                      (check check-fn label model))
                    checks)}))

(defn summarize
  "Given results from run-checks across many events, return a concise summary.
  Shows pass/fail counts per check and lists failing IRIs."
  [all-results]
  (->> all-results
       (mapcat :results)
       (group-by :label)
       (map (fn [[label results]]
              (let [fails (->> all-results
                               (filter (fn [r]
                                         (some #(and (= label (:label %))
                                                     (= :fail (:result %)))
                                               (:results r))))
                               (mapv :iri))]
                {:label label
                 :pass (count (filter #(= :pass (:result %)) results))
                 :fail (count (filter #(= :fail (:result %)) results))
                 :failing-iris fails})))
       (sort-by :fail >)))

(defn run-and-summarize
  "Convenience: run all checks over a seq of transformed events and summarize."
  [checks transformed-events]
  (->> transformed-events
       (map #(run-checks checks %))
       summarize))
#+end_src

(def statement-query

(def has-classification
  "Statement must have a cg:classification."
  {:label :has-classification
   :check-fn (fn [m]
               (seq ((rdf/create-query
                      "select ?c where { ?a a :cg/Statement ; :cg/classification ?c }") m)))})

(def has-proposition
  "Model must contain a cg:GeneValidityProposition."
  {:label :has-proposition
   :check-fn (fn [m]
               (seq ((rdf/create-query
                      "select ?p where { ?p a :cg/GeneValidityProposition }") m)))})

(def unpublish-has-date
  "An unpublished model must have a contribution with activityType cg:Unpublished and a date.
  Fixes: website_events.clj using :cg/Unpublisher instead of :cg/Unpublished."
  {:label :unpublish-has-date
   :check-fn (fn [m]
               (let [unpub-q (rdf/create-query

*** Website Event Checks

#+begin_src clojure
(defn check-website-event
  "Validate a website event map against the clojure.spec definition.
  Returns {:result :pass/:fail :explain ...}"
  [website-event]
  (if (nil? website-event)
    {:result :skip :reason :no-website-event}
    (if (s/valid? ::website-events/event-data website-event)
      {:result :pass}
      {:result :fail
       :explain (s/explain-data ::website-events/event-data website-event)})))

(defn run-website-event-checks
  "Run spec validation over website events from a seq of transformed events."
  [transformed-events]
  (let [results (->> transformed-events
                     (map (fn [e]
                            {:iri (::event/iri e)
                             :check (check-website-event
                                     (:gene-validity/website-event e))})))]
    {:pass (count (filter #(= :pass (-> % :check :result)) results))
     :fail (count (filter #(= :fail (-> % :check :result)) results))
     :skip (count (filter #(= :skip (-> % :check :result)) results))
     :failures (->> results
                    (filter #(= :fail (-> % :check :result)))
                    (mapv #(select-keys % [:iri :check])))}))
#+end_src

** Incremental Workflow

The intended workflow while applying fixes from =schema-cleanup.org=:

#+begin_src clojure
;; 1. Load the curated UUID corpus (all versions of each GDM, spanning
;;    old and new SOP/schema) plus a front/back epoch sample for breadth.
(def corpus-events (load-corpus source-file sample-corpus))
(def epoch-events (load-epoch-sample source-file 50)) ; 50 oldest + 50 newest

;; 2. Combine into a single sample set
(def sample-events (concat (mapcat val corpus-events) epoch-events))

;; 3. After each fix, re-evaluate the changed namespace and re-run:
(tap> (run-and-summarize all-checks sample-events))

;; 4. Inspect the version history of a specific GDM (useful to see how
;;    the model changes across SOP versions for one curation):
(run! #(-> % :gene-validity/model rdf/pp-model)
      (get corpus-events "815e0f84-b530-4fd2-81a9-02e02bf352ee"))

;; 5. Compare first vs. last event for a GDM to see SOP/schema evolution:
(let [versions (get corpus-events "815e0f84-b530-4fd2-81a9-02e02bf352ee")]
  (tap> {:first (-> versions first :gene-validity/model rdf/to-turtle)
         :last  (-> versions last  :gene-validity/model rdf/to-turtle)}))

;; 6. Run website event checks separately:
(tap> (run-website-event-checks sample-events))

;; 7. Drill into a specific failure:
(let [failing-iri "..."]
  (->> sample-events
       (filter #(= failing-iri (::event/iri %)))
       first
       :gene-validity/model
       rdf/pp-model))
#+end_src

** Corpus Selection Guide

To find events covering a specific dimension, use these patterns in the REPL
before adding a UUID to =sample-corpus=. When selecting for SOP version, target
the appropriate region of the event sequence: old SOPs at the front, new SOPs at
the back. Prefer GDMs with long recuration histories — a single UUID that has been
recurated across SOP versions covers more ground than several single-version entries.

#+begin_src clojure
;; Find a curation using a specific old SOP version (look near the front)
(def sop-query (rdf/create-query "select ?s where { ?a a :cg/Statement ; :cg/specifiedBy ?s }"))

(event-store/with-event-reader [r source-file]
  (->> (event-store/event-seq r)
       (take 500)           ; early events = old SOP versions
       (map transform-curation)
       (filter #(some-> % :gene-validity/model sop-query first str
                          (str/includes? "GeneValidityCriteria4")))
       (map #(-> % ::event/value (re-find #"[0-9a-f-]{36}")))
       first))

;; For a newer SOP version, sample from the back
(event-store/with-event-reader [r source-file]
  (->> (event-store/event-seq r)
       (take-last 500)      ; late events = newer SOP versions
       (map transform-curation)
       (filter #(some-> % :gene-validity/model sop-query first str
                          (str/includes? "GeneValidityCriteria10")))
       (map #(-> % ::event/value (re-find #"[0-9a-f-]{36}")))
       first))

;; Find a GDM that has been recurated across multiple SOP versions
;; (good single corpus entry that exercises both old and new GCI schemas)
(event-store/with-event-reader [r source-file]
  (->> (event-store/event-seq r)
       (map #(-> % ::event/value (re-find #"[0-9a-f-]{36}")))
       frequencies
       (filter #(< 3 (val %)))      ; appeared 4+ times = multiple versions
       (sort-by val >)
       (take 5)))

;; Find a curation with functional alteration evidence
(def fa-query

(event-store/with-event-reader [r source-file]

       (map transform-curation)
       (filter #(seq (fa-query (:gene-validity/model %))))

(def unpub-query

(event-store/with-event-reader [r source-file]

  (->> (event-store/event-seq r)
       (take-nth 50)        ; sample every 50th event for speed
       (map transform-curation)
       (map #(some-> % :gene-validity/model sop-query first str

** Suggested Fix Order

Apply fixes in this order to minimize cascading failures and make progress
visible after each step:

1. =add_legacy_website_id.sparql= — isolated SPARQL change, no Clojure
2. =validation.clj= — fixes the test harness itself; must come early
3. =sepio_model.clj= =assertion-query= + =approval-activity-query= — legacy ID
4. =gene_validity.clj= =add-iri-fn= — Kafka key; fixes =:has-kafka-iri=
5. =website_events.clj= =:cg/Unpublisher= → =:cg/Unpublished= — fixes unpublish detection
6. =user.clj= query updates — dev experience only, no production impact
